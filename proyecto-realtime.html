Desarrollo Web — 2024 — Editor colaborativo · Google Docs-like

Editor colaborativo de documentos en tiempo real

React 18 + TSSocket.io + RedisTipTap / ProseMirrorPostgreSQL + PrismaZustand

Google Docs local: múltiples usuarios editando el mismo documento, cursores de colores, comentarios anclados y sincronización por Operational Transformation. Auto-save cada 2s, reconexión con cola offline y despliegue escalable con Redis Adapter.

Objetivo

Construir una aplicación de edición colaborativa que demuestre habilidades avanzadas en WebSockets, sincronización de estado y resolución de conflictos. No es un chat con editor, es un sistema donde cada pulsación se transforma en una operación versionada, se ordena en el servidor y se replica a todos sin perder ni una letra.

Stack tecnológico

React 18 + TypeScriptZustandTipTap / ProseMirrorNode.js + ExpressSocket.ioRedis AdapterPostgreSQLPrismaNextAuth / PassportVercelRailwayRedis

Frontend

React 18 + TS con TipTap (ProseMirror) para rich text. Zustand para estado local + selección/cursores. TipTap extensions para bold/italic, headings, listas, links, imágenes, code blocks y tablas.

Backend

Node + Express + Socket.io. Redis Adapter para escalar horizontalmente: N instancias comparten el bus. Prisma sobre PostgreSQL para persistencia versionada.

Infra

Vercel (frontend) + Railway (API, Postgres, Redis). Redis para sesiones, presencia y rate limiting. Deploy con variables por entorno y healthchecks.

Arquitectura en tiempo real

Estrategia de sincronización — OT

Cada cambio es una operación atómica. El servidor ordena por timestamp + userId y re-emite. Conflictos: last-write-wins con reloj del servidor como fuente de verdad; el cliente rebasa su estado con la versión confirmada.

{
  type: "insert" | "delete" | "format",
  position: number,
  content?: string,
  length?: number,
  userId: string,
  timestamp: number
}
Por qué OT y no solo broadcast: sin transformación, dos inserts en la misma posición duplican o pierden texto. OT ajusta position según ops concurrentes ya aplicadas.

Manejo de conexiones

  • Reconexión automática con backoff
  • Queue offline en IndexedDB
  • Sync al reconectar (replay)
  • Heartbeat 30s → detecta caída

Presencia y cursores

  • Cliente reporta selection cada 150ms throttled
  • Server broadcast a room con color único asignado
  • Nombre junto al cursor + timeout 5 min inactividad
  • Lista de avatares en header del doc

Base de datos

Modelo Prisma con versionado. DocumentContent guarda el JSON de TipTap actual; DocumentVersions guarda snapshots incrementales para historial y restore sin recalcular diffs.

Autenticación

NextAuth con JWT + refresh, OAuth Google/GitHub, invitaciones firmadas por email con expiración 7 días y link de un solo uso.

Búsqueda

PostgreSQL tsvector + tsquery con trigger en DocumentContent.content_json → índice GIN. Filtros combinables y ranking por relevancia.

Flujo cercano

Abres un doc → entras a room:doc:{id} → ves 2-3 cursores moviéndose, alguien escribe “Hola” y aparece letra a letra. Seleccionas “Hola” → ⌘ B → se envía {type:"format", position:0, length:4} → todos ven negrita al instante. Dejas un comentario en “Hola” → hilo → @mencionas → email + badge. Cierras pestaña → reconexión guarda tu cursor 15s en gris antes de quitarlo. Exportas a PDF con un clic.
